# FM-1+VA preset write on FM-1_098, 2026-10-14

Run to check issue 250 (the FM1 restarting on a write on FM-1_096 and FM-1_097), on a different
unit running `FM-1_098`, over USB from macOS Chrome, development build. No timing change: the
editor's own write, paced as `fm1VaPresetWriteTiming` gives for FM-1_096 and later
(320 ms apart, no wait for a reply).

- Version: `FM-1_098` (build date not recorded)
- Source: **Piano & Electric Piano** from the bundled mene311 catalog group, imported into a new
  library bank, then written with **Write patches to the FM1…**

| Run | FM1 bank | Presets        | Result                                                                                                                                                                                                               |
| --- | -------- | -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | A        | 32, three kept | The FM1 stayed up. Presets 003, 007, and 031 held Virtual Analog presets and were left as they were, as a DX7 patch never replaces one. Slots 001 and 002 took the new patches; the rest of the bank was not checked |
| 2   | B        | 32, none kept  | The FM1 stayed up. The dialog listed all 32 presets of bank B as replaced. No stop, error, or restart                                                                                                                |

## Run 2 log

The exported MIDI log (`fm1-midi-log-2026-10-14T20-53-10.txt`) keeps only the end of the run:
presets 054–064, so 033–053 are not in it.

- Each write is 231 bytes (`F0 43 00 7D 04 <slot> …`), followed by a read of the same preset
  (`7D 10 <slot>`), and the FM1 answers the read about 180 ms after it is sent.
- The writes are about 120 ms apart after each read-back, about 320 ms from one write to the next.
- Every write in the log is answered by its read-back. Nothing stops, and no error is logged.
- Names carried: 063 `PERCUSSION`, 064 `WHAT IF`.
- After the run the FM1 took a Program Change and the 155 parameter changes of a patch click.

## Not recorded

- Whether every preset read back as written. The editor stops at the first that does not and says
  so; no such stop was reported, but presets 033–053 are not in the log.
- The state of the FM1 before the run, apart from the three Virtual Analog presets in bank A.
- Whether a Device Manager backup was taken before the run.

## Findings

- A 32-patch FM bank wrote to banks A and B on `FM-1_098` without the FM1 restarting, so issue
  250's crash on the first write is not reproduced there.
- That fits the write path not having changed since 2026-10-06. It leaves the reporter's FM1
  state, or `FM-1_096` and `FM-1_097` on their unit, as the open question.
