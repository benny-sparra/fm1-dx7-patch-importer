# M-VAVE V16: hardware run, 2026-10-23

Results of `stock-v16-run-sheet.md` on the orange FM1, already on V16 since 2026-10-22, with the
editor at `feature/v16-effect-controllers` (PR #349) and the development FX probe's **V16 research**
mode. Each step keeps the firmware's prediction (research notes, "What the firmware shows") beside
what the FM1 did.

## Summary

Confirmed on this FM1, each as the firmware analysis predicted:

- V16 answers the identity query as `FM-1_016`.
- CC 70–93 on Effect Ch are the editor's 24 effect parameters in order, clamped to V15's limits
  (Cutoff 107, Q 10, types 2, the rest 100), with each switch on for any value but 0. CC 0–23 no
  longer reach the effects, and CC 94 and 95 do nothing. The FM1 echoes none of it over MIDI.
- Effect controllers change the live FX group only: SAVE offers Globe and ALL for them, changing
  preset leaves them, and a power cycle without saving restores the stored group.
- PR #349's sends: a slot click sends no effects, and an effect edit and its undo send only the
  controller that changed, at CC 70 + n.
- A single-voice dump and DX7 parameter changes reach the edit buffer of Voice 1's preset.
- SAVE, opened from a voice editing page, offers Preset, which stores the edited patch over the
  preset; it survives a power cycle.
- Bank Export sends one standard 4104-byte 32-voice bulk dump, `F0 43 00 09 20 00`, over USB.

Found on the way: V16 has no GLOBE MIDI Ch, only one for each Voice; SAVE offers only what the
page it opens from can save; and the FM1 shows Cutoff in hertz (64 as 2789 Hz).

Not checked: which Voice a dump reaches with two Voices On (step 5, items 3–5 and 7), sending a
bank (step 6), Bank Export without USB and **Receive patch…** (step 7's last checks), and whether
a short press of SAVE on a voice page offers Preset as a hold does.

## Setting up

1. Quit anything else using the FM1's MIDI.
2. Start the dev server (`npm run dev`) and open the editor in Chrome. Switch **MIDI online**, and
   choose the FM1 as both **Output** and **Input monitor** in **Settings**.
3. On the FM1, note **Effect Ch** (stock default 2): **2**. Set the editor's **FX channel** to
   match. Keep the editor's **Note channel** on 1, different from Effect Ch, so CC 7, CC 11, and
   notes 0–26 on Effect Ch cannot be mistaken for anything else.
4. On the FM1, open PRESETS and select each Voice in turn. Note its MIDI Ch, On/Off, and preset.
   V16 has no single MIDI Ch on GLOBE: each of Voices 1–8 has its own, as the firmware's Voice
   records (channel 0–16, 0 = All) predicted.

   | Voice | MIDI Ch               | On/Off | Preset |
   | ----- | --------------------- | ------ | ------ |
   | 1     | All                   |        |        |
   | 2     | All                   |        |        |
   | 3–8   | 3–8, each its own one |        |        |

5. Open **MIDI log** in the editor and keep it open: every send below is recorded there. Copy the
   log into the results when each step finishes.

## 2. The editor sends no effects

1. Click a slot in bank A, then open a patch in the editor and move every effect control.
2. In the MIDI log, check no Control Change went out on the FX channel. Record any that did.

This run used PR #349, which sends V16 its effects at CC 70–93 only as they are edited, so this
step checks that instead: a slot click sends no effects, and an effect edit sends CC 70 + n.

**Slot click (A01, `{KC}Piano\`).** The log shows `C0 00` (Program Change 0, channel 1), then the
163-byte single-voice dump `F0 43 00 00 01 1B …`, and no Control Change on any channel. As
intended.

**Opening A01 in the editor** (11:31:31) sent the Program Change and the voice dump, and no
Control Change.

**Effect edits.** The editor disables an effect's controls while it is off, so the Filter was
switched on first:

| Edit                   | Sent                               | Meaning                      |
| ---------------------- | ---------------------------------- | ---------------------------- |
| Filter on              | `B1 46 01`                         | CC 70 = 1 on channel 2       |
| Cutoff, one drag       | `B1 48 01`, `B1 48 07`, `B1 48 08` | CC 72 = 1, 7, 8 on channel 2 |
| Undo (Cmd+Z), 11:32:02 | the voice dump, then `B1 48 00`    | Cutoff back to the patch's 0 |

The undo sent only the controller that changed, and not CC 70, whose switch the undo left on. It
also resent the whole voice, as the editor's sync does for an undo on every firmware, though only
an effect changed: harmless, and not new in PR #349.

What the FM1 showed: the Filter came on with CC 70, and Cutoff showed 8 after the drag and 0
after the undo, audibly. Whether the slot click played Piano and left the FX group alone was not
noticed; step 5 checks the slot click again.

## 3. The old controllers, CC 0–23

1. Open **FX probe (dev)** in the footer and choose **V16 research**.
2. Hold a note on the FM1, and on its FX page watch the current FX group.
3. Send each of CC 0–23 at 0, then 127, then the value the FX page showed before. Note anything that

   notes, but only on a Voice's channel, so on Effect Ch they should do nothing unless a Voice

Run as part C of the timed sweep (`stock-v16-sweep.js`, below), for the old controllers V16
reads differently rather than all 24:

| CC  | Sent   | V15 meaning | Effects on V16 |
| --- | ------ | ----------- | -------------- |
| 1   | 0, 127 | Filter Type | unchanged      |

| 11  | 0, 127 | Delay Mix   | unchanged      |

reached them as modulation, volume, and expression; the sweep left CC 1 at 127, full

## 4. The new controllers, CC 70–93

For each controller, with the matching effect's page showing on the FM1 and a note held, send each
of the probe's suggested values (0, 1, 63, 64, 126, 127) and note which parameter moves and what
the FM1 shows. Then send the value it showed first, so the FX group is left as it was.

Firmware: each group of four is the editor's own effect parameters in order, with V15's limits,
and a larger value is clamped rather than scaled:

- The first of each group turns its effect on at any value but 0, so 1, 63, and 127 all show on.
- 71 and 75, the Filter and Reverb types, show the last type (High Pass, Plate) from 2 up.
- 72, Filter Cutoff, shows 107 from 107 up; 73, Q, shows 10 from 10 up.
- Every other parameter shows 100 from 100 up, so 126 and 127 both show 100.
- The FM1's FX page jumps to the effect each controller changes.

**Result: every controller matched the firmware's reading.** The run used the timed sweep in
`stock-v16-sweep.js` (beside this sheet) rather than six values for each controller: it held
middle C on channel 1 and sent each Control Change on channel 2, three seconds apart, with what
the FM1 should show, and the FX page was watched for any difference. The log is
`stock-v16-sweep-2026-10-23.json`.

| Sent                      | Expected and shown                                                                                                                                                                      |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| CC 70–93 at 127, in order | Each effect switched on by its first controller; Filter and Reverb Type at High Pass and Plate; Filter Cutoff 107 and Q 10; every other parameter 100; the FX page moved to each effect |
| CC 71 at 0, 1, 2          | Low Pass, Band Pass, High Pass                                                                                                                                                          |
| CC 74 at 0, then 1        | Reverb off, then on                                                                                                                                                                     |
| CC 72 at 64               | Cutoff 64                                                                                                                                                                               |
| CC 94 and 95 at 1         | Nothing changed                                                                                                                                                                         |

The parameter names on the FM1 matched the sweep's, which are the editor's: Delay Decay, Rate,
Mix; Distortion Gain, Tone, Level; Chorus and Phaser Freq, Depth, Mix. The FM1 sent nothing back
during the sweep, so V16 does not echo an effect change over MIDI.

So V16's map is V15's CC 0–23 with 70 added, values clamped to V15's limits rather than scaled,
which is what PR #349 sends.

Then:

1. Does SAVE now offer **Globe**, as an unsaved FX change? **Yes.** SAVE, on the FX page of group
   FX001, offered Knob1 **ALL** and Knob2 **Globe**, with Knob3 Preset and Knob4 Pattern greyed out
   ([photo](stock-v16-2026-10-23/save-after-fx-controllers.jpg)). The effect controllers change the
   shared FX group, which only Globe or ALL saves. The popup read **CutOff: 2789Hz** after CC 72 =
   64: the FM1 shows Cutoff in hertz, not as the 0–107 the controller sets. Preset was greyed out
   although the editor had sent A01 as a single-voice dump earlier; step 5 checks whether a dump
   counts as an unsaved preset edit.
   Selecting other presets with the preset knob left every effect as the sweep set it: changing
   preset does not change the FX group on V16, as its release notes say, which is why a slot click
   sends no effects there (PR #349). SAVE again is Cancel; nothing was saved.
2. Switch the FM1 off and on without saving. Is the FX group as it was before the step? **Yes.**
   After a power cycle FX001 was as stored, every effect off, and the modulation the sweep's CC 1
   left at 127 was gone too. Effect controllers change the live FX group only; it reaches storage
   through SAVE, Globe or ALL, and is otherwise lost at power-off, as turning the FM1's own knobs

3. Do the six effects' order and On/Off states match the editor's six Enabled switches, or does a

## 5. Where a patch lands with eight Voices

Use two Voices on different channels: Voice 1 on channel 1 and Voice 2 on channel 3, both On, each
on a different preset you can tell apart by ear. Turn the other Voices off.

Firmware:

- A Program Change loads its program into every Voice that is On on its channel or on All.
- A dump and the parameter changes edit the preset loaded on the Voice selected on the FM1's
  screen, whatever channel they come on. Every Voice playing that preset hears the edit.
- The edit is unsaved and lives in RAM until SAVE.
- A dump is applied only while a flag the analysis could not trace is set. If no dump is ever
  heard, say what the FM1 shows.

This run had only Voice 1 On, on All, so it checks the dump and the parameter changes on one Voice;
the selected-Voice prediction (items 3 and 4) is left for another run.

log was lost on reload. It was run again from a power cycle.

## 7. Bank Export

Firmware:

- Export offers banks A–D. It sends one message of 4104 bytes, `F0 43 0n 09 20 00`, the bank's
  4096 bytes, a checksum, and `F7`, over USB-MIDI only.
- The FM1 shows **Connect USB** without a USB host and **USB Busy** while a transfer runs.
- The analysis reads bytes 4–5 as `20 00` through a paired instruction, so check them.
- `n` should be the FM1's MIDI channel minus one, or 0 for All. V16 has no GLOBE MIDI Ch, only one
  for each Voice; Voice 1, the only one On, was on All.

Capture what the FM1 sends, with nothing else listening:

1. Close the editor's tab. Open `https://127.0.0.1:5174/firmware/` from the dev server, which has
   no MIDI code of its own.
2. In its console (allow MIDI and SysEx when asked), paste the snippet below. It sends nothing:
   it records every message from the FM1 for 60 seconds, then downloads them as a JSON file.
3. While it records, start Bank Export on the FM1 for a bank you can recognise.
4. Move the downloaded `stock-v16-bank-export-<date>.json` beside this sheet.

```js
{
  const access = await navigator.requestMIDIAccess({ sysex: true })
  const input = [...access.inputs.values()].find((port) => /fm.?1|usb composite/i.test(port.name))
  if (!input)
    throw new Error(`No FM1 input. Inputs: ${[...access.inputs.values()].map((p) => p.name)}`)
  console.log('Recording from', input.name, 'for 60 s. Start Bank Export on the FM1 now.')
  const start = performance.now()
  const hex = (bytes) => Array.from(bytes, (byte) => byte.toString(16).padStart(2, '0')).join('')
  const messages = []
  const hear = (event) =>
    messages.push({
      at: Math.round(performance.now() - start),
      bytes: event.data.length,
      hex: hex(event.data),
    })
  input.addEventListener('midimessage', hear)
  await new Promise((resolve) => setTimeout(resolve, 60_000))
  input.removeEventListener('midimessage', hear)
  console.log(messages.length, 'messages recorded')
  const file = new Blob([JSON.stringify({ input: input.name, messages }, null, 2)], {
    type: 'application/json',
  })
  const link = document.createElement('a')
  link.href = URL.createObjectURL(file)
  link.download = `stock-v16-bank-export-${new Date().toISOString().slice(0, 10)}.json`
  link.click()
}
```

| Messages | Total bytes | First bytes of each | Time from first to last | Notes                                   |
| -------- | ----------- | ------------------- | ----------------------- | --------------------------------------- |
| 1        | 4104        | `F0 43 00 09 20 00` | one message             | bank A, as remembered; checksum correct |

**Result: as the firmware showed.** Bank Export sent one standard Yamaha 32-voice bulk dump,
`F0 43 00 09 20 00`, 4096 bytes of packed voices, the checksum `00` (`(−sum) & 7F`, which the
bytes give), and `F7`, every data byte 7-bit, and nothing else in the 90 seconds. So `n` was 0,
with Voice 1 on All. The capture is `stock-v16-bank-export-2026-10-23.json`, recorded by
`stock-v16-bank-export-capture.js` on the firmware page, which sends nothing.

The voices are bank A as this FM1 held it: 01 `j.piano 7+`, then the stock bank's names (ORGAN 1,
SYN LEAD 1, SYN PAD 1, and so on to SYN PAD 8), with 05 `j.piano 7+` as saved in step 5. Voice 05
differs from 01 only in OP1's output level (packed byte 99: 33 against 99), the value step 5's edit
left; 01 is the library's patch as sent, and was most likely stored on the FM1 by hand earlier in
the day rather than by anything the editor sent. A Bank Export therefore reads a stock FM1's bank
back in the format the editor's DX7 bank import already reads.

## What the results decide

- Step 4 gives the V16 controller map. If the six groups line up with the editor's 24 effect
  parameters, as the firmware predicts, V16 gets `effectControllers` back through a range of its
  own in the firmware profile and its controllers at CC 70–93, the editor's numbers plus 70, with
  tests from this run's values.
- Each answer that matches the firmware moves from **Likely** to **Confirmed** in the research
  notes; one that differs replaces the firmware's reading there.
- Step 4's SAVE and power-cycle answers decide whether a patch's effects may be sent at all, since
  on V16 they change the shared FX group every Voice hears.
- Step 5 decides whether the editor must say which Voice it edits, and whether a slot click
  should still send a Program Change.
- Step 6 rewords the bank destination instructions for V16.
- Step 7 decides whether a bank receiver is possible without any new message sent.
